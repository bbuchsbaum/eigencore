# Eigencore 1.2 reusable-workflow contract

- Status: frozen implementation contract
- Contract version: 1
- Package target: 1.2.0
- Date: 2026-08-25
- Gate: `bd-01KZZYZ28F0TMGVFKNSQCDKY7V`

## Purpose

Eigencore 1.2 makes a spectral computation reusable without allowing reused
state to outrank current-operator evidence. A plan becomes an immutable,
executable decision. A restart state may accelerate a later solve, but it may
not carry convergence, a certificate, or operator-dependent quantities across
an incompatible transition. Every returned result identifies what was planned,
what actually ran, why a fallback occurred, how much logical work was done,
and which retained objects consume memory.

This document freezes the public names and semantic boundaries shared by the
1.2 implementation Motes. It is normative: implementation and documentation
must use these names or amend this contract deliberately before the dependent
Motes close.

The primary readers are eigencore implementers and reviewers. Downstream users
need the resulting public guide, not the repository history recorded here.

## Three rules

1. **A plan is a value, not a suggestion.** Executing a plan does not rerun the
   planner or reread route-affecting global options.
2. **Reuse is evidence-scoped.** Basis vectors may cross a compatible operator
   revision; recurrences, locked claims, cached actions, projections,
   convergence, and certificates may not.
3. **The result describes the executed computation.** Planned route, actual
   route, fallback, work, memory, state transition, and current certificate are
   separate typed records rather than overloaded strings.

## Current-state evidence and API friction

The 1.1 implementation establishes the numerical boundary that 1.2 preserves:
all promoted paths certify in original coordinates, warm starts are hints, and
an invariant supplied subspace is discarded when it cannot establish target
identity. The reusable-workflow API is nevertheless incomplete.

| Claim | Status | Evidence | 1.2 consequence |
|---|---|---|---|
| Plans are descriptive and omit the problem and original method descriptor. | Confirmed | `new_plan()` in `R/problem.R` stores only problem type, requested size, method label, target, reasons, fallback, and controls. | A 1.2 plan retains the problem, request, method descriptor, execution controls, policy, and identity. |
| `solve(problem)` replans on every call. | Confirmed | `solve.eigencore_eigen_problem()` and `solve.eigencore_svd_problem()` call `plan_solver()` immediately. | `solve(plan)` dispatches the stored plan; `solve(problem)` remains the compatible replanning entry point. |
| Route-affecting options can be read after planning. | Confirmed | `getOption("eigencore.*")` occurs in planning and solve helpers. | Planning canonicalizes every route-affecting option into `planner_policy`; execution reads the snapshot only. |
| Result `method` and plan `method` are expected to agree even though certified routes may fall back. | Confirmed | `tests/testthat/test-result-contracts.R` asserts `fit$method == fit$plan$method`; SVD code rewrites route metadata around fallbacks. | `planned_method` and `actual_method` are distinct; legacy `method` aliases `actual_method`. |
| Operators lack identity and revision semantics. | Confirmed | `linear_operator()` stores dimension, callbacks, dtype, structure, name, and metadata only. | Every operator exposes an `eigencore_operator_identity`. |
| Warm starts expose provenance but no reusable state object. | Confirmed | `R/warm_start.R` accepts a basis hint and explicitly excludes recurrence reuse. | `eigencore_restart_state` adds opt-in basis and eligible same-operator payload retention. |
| Work fields are route-specific and partly flat. | Confirmed | result builders expose `matvecs`; warm-start routes add block/column counts; `diagnostics()` conditionally appends them. | Every iterative result carries one `eigencore_work` record with shared semantics. |
| `restart` is method-specific diagnostics. | Confirmed | result objects store heterogeneous `restart` lists used by print and diagnostics methods. | Legacy `restart` remains diagnostic; reusable state is named `restart_state` and never inferred from `restart`. |
| Retained-memory and serialization capability are not public contracts. | Confirmed | no public accessor or schema/version checks exist. | Plans and restart states report retained bytes and portability explicitly. |

The main API friction is semantic overloading. A newcomer would reasonably
expect `plan_solver()` to produce something that `solve()` can execute and
`method` to name what ran. In 1.1 neither expectation is uniformly true. The
1.2 surface fixes those meanings instead of explaining around them.

## Frozen public names

### New exported functions

| Name | Contract |
|---|---|
| `operator_identity(x)` | Return the typed identity and revision of an operator, problem, plan, state, or result. |
| `restart_state(x, retention = c("basis", "same_operator"))` | Extract or construct an opt-in reusable state from a certified result. |
| `work(x)` | Return an `eigencore_work` record. For a legacy result, return a partial record with `complete = FALSE`. |
| `retained_bytes(x)` | Return the known retained byte count with a component breakdown and completeness flag. |

For a single operator or restart state, `operator_identity()` returns one
`eigencore_operator_identity`. For an eigen/SVD problem, plan, or result it
returns a named list with `A` and, when present, `B`; each entry is a typed
identity record.

### Frozen public classes

| Class | Role |
|---|---|
| `eigencore_plan` | Immutable executable plan. |
| `eigencore_operator_identity` | Logical identity, revision, coordinate signature, and portability. |
| `eigencore_planner_policy` | Canonical snapshot of route-affecting policy. |
| `eigencore_restart_state` | Optional public basis plus eligible same-operator method payload. |
| `eigencore_state_transition` | Decision record describing accepted reuse and invalidation. |
| `eigencore_work` | Typed logical work and phase timing. |
| `eigencore_memory` | Retained-memory breakdown and completeness. |
| `eigencore_fallback_reason` | Machine-readable fallback code and human-readable message. |

The corresponding validation failures use `eigencore_plan_error` and
`eigencore_restart_state_error`, both of which inherit from `error` and
`condition`.

### New S3 method

```r
solve.eigencore_plan <- function(
  a,
  b,
  restart_state = NULL,
  reuse = c("auto", "basis_only", "same_operator"),
  retain_state = c("none", "basis", "same_operator"),
  replan = FALSE,
  ...
)
```

`solve(plan)` executes the stored route. `replan = TRUE` is the only switch
that permits a new planner decision; it replans from the embedded problem and
original method descriptor under the current policy, then executes and returns
that new plan in the result. It does not mutate the old plan.

Apart from `restart_state`, `reuse`, `retain_state`, and `replan`, execution
arguments are frozen in the plan. Named entries in `...` that attempt to
override the requested size, method, target, tolerance, vector mode,
certification, iteration budget, or dense-fallback policy are errors. An empty
`...` is accepted for S3 compatibility.

### Extended existing signatures

`linear_operator()` gains these trailing arguments:

```r
operator_id = NULL,
revision = NULL,
portable = FALSE
```

- `operator_id` is a non-empty character scalar naming one logical operator
  lineage.
- `revision` is a non-empty character scalar naming the values/behavior within
  that lineage.
- `portable = TRUE` is a user assertion that a callback operator and its
  captured environment can be restored in another R session. Eigencore still
  validates schema, identity, dimensions, dtype, and structure at execution.
- Omitting identity on a callback operator creates a session-local identity.
  Such an operator supports same-session planning and reuse but is not portable.

`plan_solver()` methods gain explicit execution controls after their existing
request and method arguments. Eigen plans freeze `tol`, `maxit`, `vectors`,
`certify`, and `allow_dense_fallback`; SVD plans freeze `tol`, `vectors`,
`certify`, and `allow_dense_fallback`. Defaults remain identical to 1.1.

`solve.eigencore_eigen_problem()` and `solve.eigencore_svd_problem()` retain
their 1.1 signatures and behavior. They create and execute a fresh plan. The
high-level `eig_partial()` and `svd_partial()` APIs remain compatible.

### New result fields

Every 1.2 eigen and SVD result contains:

```text
planned_method
actual_method
fallback_used
fallback_reason
work
memory
state_transition
restart_state     # NULL unless retain_state != "none"
```

Legacy `method` remains and is exactly equal to `actual_method`. Legacy
`matvecs`, `restart`, and route-specific diagnostic fields remain available.
The result's `plan$planned_method` does not change when certification selects a
fallback.

## Executable plan contract

### `eigencore_plan` schema version 1

An executable plan is a list with class `eigencore_plan` and these required
fields:

| Field | Meaning |
|---|---|
| `schema_version` | Integer `1L`. |
| `problem` | Frozen eigen or SVD problem, including operator objects. |
| `problem_type` | Compatibility label: `"eigen"` or `"svd"`. |
| `requested` | Frozen `k` or rank. |
| `target` | Existing display label. |
| `method_descriptor` | Original typed method request, including `auto()`. |
| `planned_method` | Canonical route label selected at planning. |
| `method` | Compatibility alias equal to `planned_method`. |
| `reasons` | Existing human-readable planner reasons. |
| `fallback` | Existing fallback policy description. |
| `controls` | Canonical method controls consumed by dispatch. |
| `execution` | Frozen tolerance, budgets, vector mode, certification, and dense-fallback policy. |
| `planner_policy` | Typed snapshot of every route-affecting package option. |
| `operator_identity` | Identity record for `A` and, when present, metric/right-hand operator `B`. |
| `serialization` | Portability, originating session, and incompatibility reason. |
| `memory` | Retained-memory record for the plan. |

The planner policy snapshot includes canonical values for all options that can
change route choice, subspace/restart budgets, dense materialization, adaptive
stopping, or promotion status. Schema version 1 contains these exact keys:

```text
eigencore.arnoldi_max_restarts
eigencore.block_dense_full_subspace_max_n
eigencore.dense_partial_lanczos_max_fraction
eigencore.dense_partial_lanczos_min_n
eigencore.promote_sparse_block_lanczos
eigencore.lobpcg_maxit
eigencore.dense_fallback_mb
eigencore.max_dense_fallback_bytes
eigencore.implicit_gram_svd_min_dimension
eigencore.promote_retained_golub_kahan
eigencore.golub_kahan_projected_stop
eigencore.golub_kahan_prefix_diagnostics
eigencore.randomized_stage_timing
eigencore.randomized_adaptive_stop
```

Canonicalization resolves defaults, invalid values, and the legacy dense-
fallback alias at planning time. Execution must not call `getOption()` for one
of these decisions. Implementation may add an option only by adding it to the
snapshot schema and its mutation tests.

### Immutability

- Planning deep-copies mutable control and policy lists.
- Executing a plan may allocate caches local to that execution but does not
  modify the public plan.
- Changing `options(eigencore.*)` after plan creation cannot change the route,
  controls, or fallback policy of `solve(plan)`.
- A result contains the exact plan value that governed its execution.
- `replan = TRUE` returns a result governed by a newly created plan; the old
  plan remains byte-for-byte unchanged.

### Plan validation

Before any operator application, `solve(plan)` validates:

1. class and schema version;
2. presence and type of every required field;
3. agreement among problem, request, target, method descriptor, controls, and
   identity records;
4. operator dimension, dtype, structure, identity, and revision;
5. plan portability against the current session;
6. the stored dispatch label against the registered 1.2 dispatch table; and
7. execution controls against method-specific bounds.

Failure is an error of class `eigencore_plan_error` with fields `code`,
`field`, `expected`, and `actual`. Required codes are
`unsupported_schema`, `missing_field`, `corrupt_plan`,
`operator_incompatible`, `session_incompatible`, `dispatch_unavailable`, and
`execution_override`.

No invalid plan silently replans. The error may recommend `replan = TRUE`.

## Operator identity and revision

### `eigencore_operator_identity` schema version 1

```text
schema_version
operator_id
revision
origin
dim
dtype
structure
portable
session_id
```

`operator_id` answers “which logical map lineage is this?” `revision` answers
“which values and behavior does this instance implement?” Equality requires
exact equality of both tokens plus dimension, dtype, and structure.

Built-in dense, CSC, and diagonal operators receive deterministic identities
from their canonical dimensions, storage, structure, and values. Composite
operators derive identity and revision from ordered parent identities and
canonical transformation parameters. The identity computation must cover all
stored values that affect `apply` or `apply_adjoint`; display names and memory
addresses are not identity.

Callback operators behave as follows:

- explicit `operator_id` and `revision` are authoritative user provenance;
- missing tokens produce opaque session-local tokens;
- `portable = FALSE` records the creating session and fails cross-session plan
  execution or same-operator reuse;
- `portable = TRUE` permits cross-session validation but does not waive shape,
  dtype, structure, schema, or method-state checks.

The creator must change `revision` whenever a callback's captured data or
behavior changes. Mutating a callback environment without changing its
revision violates the operator contract; eigencore cannot infer arbitrary
closure mutation. Plans deep-copy their ordinary R lists but do not pretend to
deep-copy or freeze an arbitrary closure environment.

Changing `revision` while retaining `operator_id` is the ordinary continuation
case, such as `A - rho B`. It is a changed operator: basis reuse may be valid,
but all operator-dependent state is stale.

## Reusable restart-state contract

### `eigencore_restart_state` schema version 1

A restart state is an immutable list with class `eigencore_restart_state` and
these fields:

| Field | Meaning |
|---|---|
| `schema_version` | Integer `1L`. |
| `basis` | Orthonormal method-independent basis in original coordinates. |
| `operator_identity` | Identity of the operator that produced the state. |
| `problem_signature` | Dimension, dtype, structure, target family, metric presence, and coordinate-space identifier. |
| `requested` | Requested `k` or rank that produced the state. |
| `method` | Actual method label that produced it. |
| `method_state` | Optional versioned same-operator payload; never required for basis reuse. |
| `provenance` | Source result, retention mode, state decisions, and invalidations. |
| `serialization` | Portability of basis and method payload. |
| `memory` | Retained-memory breakdown. |

The public basis is always expressed in original problem coordinates. It is
not a projected tridiagonal/Hessenberg basis, an implementation workspace, a
set of locked claims, or cached `A %*% Q` values.

`restart_state(result, retention = "basis")` retains only the public basis.
`retention = "same_operator"` additionally asks the producing adapter for a
versioned method payload. If that route has no stable payload, construction
still succeeds with a basis state and records `method_state_available = FALSE`;
it never exposes an internal layout merely to satisfy the request.

State retention is opt-in. Default solves return `restart_state = NULL`.

### Reuse modes

| `reuse` | Behavior |
|---|---|
| `"auto"` | Use eligible method state only for exact same-operator compatibility; otherwise use the basis when coordinate-compatible and record every invalidation. |
| `"basis_only"` | Ignore method state even when compatible; recompute all operator-dependent quantities. |
| `"same_operator"` | Require exact operator identity/revision and compatible method state; error instead of downgrading. |

### State transitions

| Transition | Public basis | Method recurrence / locked set | Cached operator actions | Projection | Residuals and convergence | Certificate |
|---|---:|---:|---:|---:|---:|---:|
| Same identity and revision; compatible method payload | reusable | reusable only when adapter version and controls match | reusable only when payload declares and validates them | recomputed unless the adapter proves the cached projection belongs to the exact same revision | recomputed | fresh |
| Same identity, new revision | reusable when coordinates match | invalidated | invalidated | recomputed | recomputed | fresh |
| Different identity, same coordinate signature | reusable only in `auto` or `basis_only` | invalidated | invalidated | recomputed | recomputed | fresh |
| Target changes within a method-compatible family | reusable as a hint | invalidated unless adapter explicitly supports the transition | invalidated | recomputed | recomputed | fresh |
| Method changes | reusable if the receiving method accepts a basis | invalidated | invalidated | recomputed | recomputed | fresh |
| Dimension, dtype, structure, metric presence, or coordinate space changes | rejected | rejected | rejected | not run | not run | not run |
| Unknown or future schema | rejected | rejected | rejected | not run | not run | not run |
| Cross-session opaque callback identity | rejected | rejected | rejected | not run | not run | not run |

Every solve returns an `eigencore_state_transition` schema-version-1 record
with `relation`, `basis_used`, `method_state_used`, `invalidated`, and
`reason`. Required relation codes are `cold_start`, `initial_subspace`,
`same_operator`, `changed_revision`, and `changed_operator`. A solve without a
restart state uses `cold_start` or `initial_subspace`; both set
`method_state_used = FALSE`.

Invalid or corrupt state errors have class `eigencore_restart_state_error` and
codes `unsupported_schema`, `coordinate_incompatible`, `operator_incompatible`,
`method_incompatible`, `stale_method_state`, `session_incompatible`, and
`corrupt_state`.

### Certificate boundary

A restart state never contains a certificate that can pass a future solve.
Historical certificate summaries may appear under provenance for audit only.
Every solve applies the current operator, recomputes projected quantities,
residuals, orthogonality, convergence, target ordering, and an original-
coordinate certificate. Failure to produce that current certificate fails the
solve exactly as it does for a cold start.

## Typed work accounting

### `eigencore_work` schema version 1

Every iterative eigen and SVD result contains a classed work record with these
fields:

```text
schema_version
complete
operator_block_calls
operator_columns
adjoint_block_calls
adjoint_columns
metric_block_calls
metric_columns
preconditioner_calls
preconditioner_columns
certification_operator_block_calls
certification_operator_columns
certification_adjoint_block_calls
certification_adjoint_columns
iterations
restarts
setup_seconds
solve_seconds
certification_seconds
total_seconds
legacy_matvecs
```

Semantics:

- A block call counts one logical application of the named map, regardless of
  whether it crosses an R callback boundary or stays in a native kernel.
- Columns count the number of vector columns presented in those logical calls.
- Forward and adjoint applications are separate; SVD work does not collapse
  them into an ambiguous matvec total.
- Metric and preconditioner applications are separate from operator work.
- Certification work is not folded into solve work. Total work is obtained by
  adding phase-specific fields deliberately.
- Setup includes factorization, identity validation, plan/state preparation,
  and other pre-iteration work. It does not invent equivalent operator calls
  for dense factorizations.
- Times are elapsed seconds measured at the named boundaries and are never
  presented as deterministic counters.
- Every counter is a non-negative whole number or `NA` when the adapter cannot
  establish it. `complete` is `TRUE` only when required counters for that route
  are known.

Legacy result field `matvecs` preserves its 1.1 route-specific value and is
copied to `legacy_matvecs`. It is not redefined as a cross-family metric.
Benchmarks and new documentation use typed columns, not `matvecs`, for
cross-solver comparisons.

`work(legacy_result)` synthesizes known fields, fills unknown fields with `NA`,
and returns `complete = FALSE`.

## Retained-memory contract

Plans, restart states, and results carry an `eigencore_memory` record:

```text
schema_version
r_bytes
native_bytes
total_bytes
complete
components
```

Required restart-state components are `basis`, `method_state`,
`cached_operator_actions`, and `metadata`. Plans report `problem`, `controls`,
`policy`, and `metadata`. `retained_bytes(x)` returns `total_bytes` and attaches
the full record as a `memory` attribute.

`r_bytes` measures retained R objects, not cumulative allocation.
`native_bytes` includes retained native allocations only when the owning
adapter reports them. `complete = FALSE` whenever native retention is unknown;
then `total_bytes` is a known lower bound. No retained-byte value is described
as peak RSS or total solver workspace.

## Serialization and versioning

Base `saveRDS()` and `readRDS()` are the persistence mechanism. Eigencore does
not introduce a second wire format in 1.2.

- Every plan, identity, restart state, work record, memory record, and method
  payload has an integer schema version.
- Major schema mismatches fail closed before operator application.
- Unknown additive fields are preserved and ignored only when the known schema
  version permits them.
- Matrix-backed plans and basis-only restart states are portable.
- Opaque callback plans are session-bound unless created with explicit
  identity/revision and `portable = TRUE`.
- A nonportable method payload does not poison a portable basis state:
  `reuse = "auto"` or `"basis_only"` invalidates the payload after restore;
  `reuse = "same_operator"` errors.
- External pointers are never serialized as valid method state.
- Deserialization does not upgrade an old plan silently. A 1.1 descriptive
  plan remains printable but `solve(old_plan)` errors with
  `unsupported_schema` and recommends replanning from the original problem.

## Provenance and fallback

The result fields have exact meanings:

| Field | Meaning |
|---|---|
| `planned_method` | Route frozen in the executed plan. |
| `actual_method` | Route that produced the returned values and certificate. |
| `method` | Compatibility alias of `actual_method`. |
| `fallback_used` | Scalar logical; `TRUE` only when actual differs from planned through an allowed fallback transition. |
| `fallback_reason` | Typed reason code plus human message; `NULL` when no fallback occurred. |

Required fallback reason codes are `certificate_failed`,
`method_state_incompatible`, `kernel_unavailable`, `numerical_breakdown`, and
`policy_permitted_fallback`. An unexpected error is not relabeled as fallback.
When present, `fallback_reason` is an `eigencore_fallback_reason` schema-
version-1 record with `code`, `message`, `planned_method`, `attempted_method`,
and a method-specific `details` list.

The plan remains the planned decision. Runtime provenance is stored on the
result and in `state_transition`; implementation must not mutate
`plan$planned_method` until it agrees with the actual route.

## Compatibility and migration from 1.1

| 1.1 workflow | 1.2 behavior |
|---|---|
| `eig_partial()` / `svd_partial()` with no new arguments | Same call shape and defaults; internally creates and executes a plan. |
| `solve(problem, ...)` | Continues to plan on each call, so current global policy may affect each call as before. |
| `plan_solver(problem, ...)` used for inspection | Returns a superset with the existing `method`, `reasons`, `fallback`, and `controls` fields preserved. |
| `fit$method` | Preserved; now aliases the actual route. |
| `fit$plan$method` | Preserved; names the planned route. It may differ from `fit$method` only when `fallback_used = TRUE`. |
| `fit$matvecs`, `fit$restart`, and current diagnostics | Preserved as compatibility fields; new code should use `work(fit)` and `fit$restart_state`. |
| `initial_subspace = Q` | Preserved as a basis hint. It does not retain or imply method state. |
| Saved 1.1 results | Accessors continue to read legacy fields; new typed records are partial and marked incomplete. |
| Saved 1.1 descriptive plans | Inspectable but not executable; fail closed with a migration message. |

Adding result fields and exports is an intentional minor-version API change and
requires snapshot, NEWS, reference, and migration updates. No 1.1 argument is
removed or reinterpreted.

## Worked contract examples

These examples freeze the intended 1.2 surface. They become executable tests as
the dependent implementation Motes land.

### Dense executable plan and policy snapshot

```r
A <- diag(c(8, 5, 3, 1))
problem <- eigen_problem(A, target = largest())

plan <- plan_solver(
  problem,
  k = 2,
  method = auto(),
  tol = 1e-10,
  vectors = TRUE,
  certify = TRUE,
  allow_dense_fallback = "auto"
)

old <- options(eigencore.dense_partial_lanczos_min_n = 1L)
fit <- solve(plan)
options(old)
stopifnot(identical(fit$planned_method, plan$planned_method))
stopifnot(identical(fit$method, fit$actual_method))
stopifnot(isTRUE(certificate(fit)$passed))
```

Changing the option after planning cannot change `fit$planned_method`.

### CSC executable plan

```r
A <- Matrix::bandSparse(
  100,
  k = c(-1, 0, 1),
  diagonals = list(rep(-1, 99), rep(2, 100), rep(-1, 99))
)
plan <- plan_solver(
  eigen_problem(A, target = smallest()),
  k = 4,
  method = lanczos(),
  tol = 1e-9
)
fit <- solve(plan, retain_state = "basis")

stopifnot(operator_identity(plan)$portable)
stopifnot(inherits(fit$restart_state, "eigencore_restart_state"))
stopifnot(retained_bytes(fit$restart_state) > 0)
stopifnot(isTRUE(certificate(fit)$passed))
```

No execution step may densify `A` unless the frozen plan explicitly permits a
dense fallback and the result reports that fallback.

### Matrix-free plan with explicit identity

```r
A <- diag(seq(10, 1))
op <- linear_operator(
  dim = dim(A),
  apply = function(X, alpha = 1, beta = 0, Y = NULL) {
    out <- alpha * (A %*% X)
    if (is.null(Y) || beta == 0) out else out + beta * Y
  },
  structure = hermitian(),
  operator_id = "example-diagonal",
  revision = "values-10-to-1",
  portable = TRUE,
  metadata = list(frobenius_norm = sqrt(sum(A^2)))
)

plan <- plan_solver(
  eigen_problem(op, target = largest()),
  k = 2,
  method = lanczos(block = 2)
)
fit <- solve(plan, retain_state = "same_operator")
stopifnot(work(fit)$operator_columns >= 2)
```

Without explicit identity, the same object works in the creating session but a
restored plan fails before invoking the callback.

### Same-operator method-state reuse

```r
first <- solve(plan, retain_state = "same_operator")
state <- restart_state(first, retention = "same_operator")
second <- solve(
  plan,
  restart_state = state,
  reuse = "same_operator",
  retain_state = "same_operator"
)

stopifnot(second$state_transition$relation == "same_operator")
stopifnot(second$state_transition$method_state_used)
stopifnot(isTRUE(certificate(second)$passed))
```

The second certificate is newly computed; it is not copied from `first`.

### Changed-operator `A - rho B` continuation

```r
A0 <- diag(seq(8, 1))
B0 <- diag(seq(0.5, 1.2, length.out = 8))

make_op <- function(rho) {
  M <- A0 - rho * B0
  linear_operator(
    dim = dim(M),
    apply = function(X, alpha = 1, beta = 0, Y = NULL) {
      out <- alpha * (M %*% X)
      if (is.null(Y) || beta == 0) out else out + beta * Y
    },
    structure = hermitian(),
    operator_id = "A-rho-B-sequence",
    revision = sprintf("rho=%.17g", rho),
    portable = TRUE,
    metadata = list(frobenius_norm = sqrt(sum(M^2)))
  )
}

p1 <- plan_solver(eigen_problem(make_op(0.10)), k = 3,
                  method = lanczos(block = 3))
f1 <- solve(p1, retain_state = "same_operator")

p2 <- plan_solver(eigen_problem(make_op(0.11)), k = 3,
                  method = lanczos(block = 3))
f2 <- solve(p2, restart_state = restart_state(f1), reuse = "auto")

stopifnot(f2$state_transition$relation == "changed_revision")
stopifnot(f2$state_transition$basis_used)
stopifnot(!f2$state_transition$method_state_used)
stopifnot(all(c(
  "recurrence", "locked", "cached_operator_actions", "projection",
  "convergence", "certificate"
) %in% f2$state_transition$invalidated))
stopifnot(isTRUE(certificate(f2)$passed))
```

## Incompatibility table

| Condition | `solve(plan)` | `reuse = "auto"` | `reuse = "basis_only"` | `reuse = "same_operator"` |
|---|---|---|---|---|
| Plan schema unknown | Error before apply | — | — | — |
| Stored operator revision differs from plan identity | Error; recommend replan | — | — | — |
| State revision differs, coordinates compatible | Plan executes | Basis only | Basis only | Error |
| State identity differs, coordinates compatible | Plan executes | Basis only | Basis only | Error |
| Dimension/dtype/structure/coordinate mismatch | Plan executes without state | Error | Error | Error |
| Method payload version unknown | Plan executes | Basis only with reason | Basis only | Error |
| Target family incompatible but basis coordinates valid | Plan executes | Basis only with reason | Basis only | Error |
| Opaque callback plan restored in new session | Error before apply | — | — | — |
| Nonportable method payload restored; basis portable | Plan executes | Basis only with reason | Basis only | Error |
| Caller tries to override frozen tolerance or method | `execution_override` error | same | same | same |

## Explicit non-goals for 1.2

- Reusing a historical certificate, convergence flag, locked status, or target
  ordering.
- Treating cached `A %*% Q`, projected matrices, or recurrences as valid after
  an operator revision changes.
- Exposing native solver workspaces or implementation-specific basis layouts as
  the public restart-state representation.
- Automatic coordinate transformations between unrelated domains.
- Mutable plans or restart states.
- A custom selected-tridiagonal eigensolver.
- Experimental structured `T_proj` updates.
- Complex GSVD expansion, broad geigen replacement, or unrelated solver
  families.
- Peak-RSS claims derived from retained R object size or `bench::mem_alloc`.
- A new cross-language serialization format.
