# Eigencore 1.3 PSD numerical and resource certification

Date: 2026-08-25

Candidate implementation: `7158cb79f7e488db54cfb49cef295a3e9062b2df`

Platform: `aarch64-apple-darwin20`, R 4.5.1, Matrix 1.7-3,
testthat 3.3.2

This report certifies the exact capability manifest implemented for 1.3. It
does not admit the optional opaque matrix-free approximation child. Timing is
diagnostic. Correctness, retained memory, R cumulative allocation, and
isolated-process peak RSS are separate measurements.

## Certification outcome

- Dedicated adversarial campaign: 230 assertions, zero failures, warnings, or
  skips.
- All PSD tests: 781 assertions across API, factor, image-space, structural,
  sparse, mutation, and adversarial contexts.
- Full source suite: 6,241 assertions, zero failures, warnings, or skips.
- A fresh source build and `R CMD check --no-manual` under the repository UTF-8
  locale policy completed with `Status: OK`.
- The capability manifest and resource probes ran against a clean-library
  installation of the same candidate source, not a package already attached
  from the developer library.

The full installed-downstream and exact-release-artifact gates remain separate
roadmap children. This report does not claim either one early.

## Independent numerical evidence

The deterministic bank includes zero and diagonal analytic forms, seeded
orthogonally rotated singular forms, repeated eigenspaces, complete and
structural Gram factors, paths, disconnected graph unions, isolated vertices,
and repaired Laplacians. The decisive oracles are independent of the
production decision being tested:

- explicit `Q diag(lambda) Q^T` actions for roots, inverse roots,
  pseudoinverses, and projectors;
- direct Moore-Penrose, projector, bilinear-form, reduction/lift, and strict
  equation residuals;
- base dense eigendecomposition only in bounded test fixtures;
- `K = L L^T` and `K = L^T L` identities for Gram paths;
- independently constructed graph components and dense small-matrix actions
  for Laplacians;
- projectors rather than raw basis columns for repeated eigenspaces.

Seeded dense cases used seeds 104729, 130363, and 155921 at scales
`1e-12`, `1`, and `1e12`. Every canonical action, block-versus-column route,
energy identity, reduction/lift law, numerical rank, and nullity passed its
operation-specific relative bound. Separate metamorphic tests covered positive
action exponents, coordinate permutation, block partitioning, null-space
contamination, and component-wise Laplacian constants.

Threshold tests used the adjacent doubles around one:
`1 - eps/2`, `1`, and `1 + eps`. They certify the inclusive positivity and rank
boundaries without decimal rounding. The scale campaign explicitly proves that
replacing the Frobenius scale by `max(1, scale)` would discard retained modes in
the `1e-12` case.

## Sparse non-densification and memory

Both resource fixtures used `n = 50,000`; a dense `n` by `n` double matrix
would require 20,000,000,000 bytes. Measurements came from fresh processes via
macOS `/usr/bin/time -l`. The matching loaded-package baseline maximum RSS was
166,871,040 bytes and peak memory footprint was 137,201,344 bytes.

| Route | Source nnz | Source bytes | Retained bytes | R cumulative allocation | Maximum RSS | Increment above baseline | Dense equivalent |
|:---|---:|---:|---:|---:|---:|---:|---:|
| sparse Gram, width 32 | 50,000 | 601,632 | 656,344 | 5,310,512 | 189,743,104 | 22,872,064 | 20,000,000,000 |
| path Laplacian | 149,998 | 2,001,480 | 1,656,616 | 150,359,816 | 282,443,776 | 115,572,736 | 20,000,000,000 |

Both factors reported `dense_n_by_n = FALSE`, passed construction
certificates, and completed four-column form application. Sparse Gram action
took 0.005 seconds and Laplacian action 0.011 seconds in these diagnostic runs.
The Gram checksum was 259399440.625; the path-Laplacian checksum was zero, as
required for the constant-column fixture. The Laplacian reported algebraic
nullity one.

Maximum RSS includes the R runtime and loaded packages. R cumulative
allocation is not peak memory, and neither value is inferred from a benchmark
framework's `mem_alloc` field. The observed maximum RSS was 0.95% and 1.41% of
the corresponding dense action alone, respectively.

## Route and reuse timing

Twenty-five eight-column form applications were measured per size. These are
local diagnostic timings, not pass/fail thresholds.

| n | diagonal setup | dense setup | diagonal actions | dense reused actions | dense rebuild plus actions | diagonal retained | dense retained |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 32 | 0.002 s | 0.001 s | 0.003 s | 0.004 s | 0.018 s | 53,320 B | 61,016 B |
| 64 | 0.000 s | 0.001 s | 0.002 s | 0.008 s | 0.028 s | 55,496 B | 87,384 B |
| 128 | 0.000 s | 0.002 s | 0.003 s | 0.021 s | 0.080 s | 59,848 B | 189,272 B |
| 256 | 0.001 s | 0.008 s | 0.004 s | 0.071 s | 0.266 s | 68,552 B | 589,656 B |

The result supports two bounded claims: the analytic diagonal route retains
linear state and is consistently cheaper for repeated form actions; reusing a
dense factor avoided the repeated decomposition and was approximately 3.5 to
4.5 times faster than reconstructing it for every action in this run. It does
not establish a universal wall-clock crossover.

## Reproduction

Install the candidate into an empty library, then run:

```sh
Rscript tools/psd-certify.R manifest
/usr/bin/time -l Rscript tools/psd-certify.R resource_sparse_gram
/usr/bin/time -l Rscript tools/psd-certify.R resource_laplacian
Rscript tools/psd-certify.R benchmark
```

Set `R_LIBS_USER` to the empty candidate library for each command. The exact
artifact gate must rerun the manifest and numerical checks against the one
tarball selected for publication; source evidence is not an artifact receipt.
