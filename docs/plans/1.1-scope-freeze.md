# Eigencore 1.1 scope freeze

Status: integrated development baseline for `release/1.1.0`.

## Ancestry

The 1.1 branch starts from `origin/main` at `36ce8ef` and reconciles the
published 1.0.2 patch line at `7ea8d58`. Their merge base is the 1.0.0 release
candidate `a8196b3`. The merge preserves both lines of development rather than
replaying or dropping the CRAN fixes.

The development version is `1.1.0.9000`; the exact release commit and source
tarball hash remain the responsibility of the final release gate.

## Included surface

Eigencore 1.1 ships the post-CRAN work already integrated on `main`:

- a public `initial_subspace` argument on `eig_partial()` and
  `solve.eigencore_eigen_problem()` for the explicitly supported real
  Hermitian Lanczos paths;
- `check_stride` on `lanczos()`, with `0L` retaining the previous full-sweep
  behavior;
- the native block Hermitian Lanczos matrix-free callback path selected by
  `lanczos(block > 1)`;
- the production implicit-Gram partial SVD route for eligible largest-target
  dense and CSC problems, with exact two-sided certification in original
  coordinates and a native Golub-Kahan fallback;
- scalar Krylov, sparse block-apply, operator-construction, and portability
  improvements described in `NEWS.md`;
- the warm-start, sparse-PCA, certificate, benchmark, and package-site
  documentation tranche; and
- every CRAN portability fix released in 1.0.1 and 1.0.2, including the
  shipped benchmark and vignette guards for R builds without memory profiling.

## Public API inventory

The exported symbol set is unchanged from 1.0.0. The intentional public API
changes are additive:

- `eig_partial(..., initial_subspace = NULL)`;
- `solve.eigencore_eigen_problem(..., initial_subspace = NULL)`; and
- `lanczos(..., check_stride = 0L)`.

Result and diagnostic objects add warm-start provenance and typed counts for
operator block calls, operator columns, and certification columns. Existing
calls with the new arguments omitted retain their prior behavior. The API
snapshot is the release-contract oracle and must change only for these reviewed
additions or later 1.1 correctness fixes.

## Planner and execution inventory

The principal new production labels and routes are:

- `native certified implicit Gram SVD (thick-restart Lanczos)` for eligible
  largest-target partial SVD problems; and
- `native block Hermitian Lanczos (matrix-free callback, thick restart,
  locking)` for explicit matrix-free block Lanczos requests.

Warm starts do not promote an otherwise unsupported method. Plans declare
whether they consume `initial_subspace`; generalized, shift-invert, and dense
fallback plans reject it. Every warm solve recomputes projected quantities,
residuals, orthogonality, convergence, and a current-operator certificate.

## Required 1.1 hardening

Before release, the existing public generalized-eigen surface must:

- certify returned left generalized eigenvectors;
- align classification policy, left-vector access, and GSVD value semantics;
- avoid silent sparse-to-dense conversion while certifying complex pencil
  eigenvectors; and
- classify finite and infinite pencil values under a documented,
  scale-invariant policy.

Certificate-facing prose must also describe evidence and limitations without
self-congratulatory or anthropomorphic language.

## Deferred from 1.1

Eigencore 1.1 does not add reusable restart/checkpoint objects, generalized
cross-solver work diagnostics, frozen executable plans, native
centered-plus-scaled CSC fusion, structured projected-matrix update kernels, a
custom selected-tridiagonal eigensolver, complex GSVD, or broad new solver
families. These items remain assigned to 1.2 or later tracker gates.

## Release evidence

The integrated candidate must pass installed tests and a clean-source
CRAN-like check, strict warm-start continuation and implicit-Gram SVD
benchmarks, generalized-eigen adversarial checks, documentation and pkgdown
builds, independent fresh-context review, and exact-artifact cross-platform
validation before 1.1.0 is published.
