# Eigencore 1.3 installed downstream PSD conformance

Date: 2026-08-25

Status: candidate gate passed. The release gate must repeat this script against
the exact `eigencore_1.3.0.tar.gz` selected for publication and replace the
pre-release eigencore receipt below. This document does not claim that the
current candidate tarball is the final release artifact.

## Outcome

The installed-only conformance script completed 50 diagnostic checks from an
arbitrary working directory with no repository-relative source access and no
triple-colon calls. It used only public APIs from clean-library installations
of eigencore, gprocrustes, and DKGE.

- The generic eigencore singular-PSD fixture passed rank, nullity, form,
  complementary projector, quotient Gram, null-invariance, block
  orthonormalization, operation-certificate, exported-operator, and RDS
  round-trip checks.
- gprocrustes passed independent O and SO polar-action oracles, objective
  checks, a diagonal compatibility fixture, coordinate permutation, and
  null-space contamination.
- DKGE passed native differential checks for the principal root, inverse root,
  support projector, PSD orthonormalization, K-Procrustes action and objective,
  effect/root-space projectors, null-space contamination, and ordinary/large
  positive rescaling.
- The gate detected and pinned one pre-existing DKGE tiny-scale divergence:
  its public `dkge_k_orthonormalize()` rejects a full-rank-in-the-seminorm block
  when `K` is scaled by `1e-12`, while eigencore retains the same two-dimensional
  support. This is a downstream differential finding, not a reason for
  eigencore to adopt DKGE's scale floor.
- rfugw adoption is explicitly deferred. Its candidate spectral uses are
  diffusion embeddings, generic structure SVDs, and post-hoc factorization of
  an already materialized dense transport plan. None needs the certified PSD
  factor algebra, and changing them would couple OT solver semantics and
  optional dependency policy to this release without a demonstrated
  certificate or resource benefit.

## Independent application evidence

### gprocrustes

For original-coordinate blocks `X` and `Y`, the application moment was formed
directly as

```text
C = X^T K Y.
```

The script also reduced both blocks through eigencore and proved that their
ordinary cross-product equals this direct moment. The O action was compared to
an independent base SVD polar factor. A separate diagonal fixture with
`C = diag(2, -1)` makes O and SO observably different: the O optimum has
determinant -1, while the independently derived proper action has determinant
+1 and the expected constrained objective. A simultaneous coordinate
permutation and independently generated null-space contamination preserve the
moment, action, and objective.

This gate does not move translation gauges, quotient meaning, objectives,
solver selection, or consensus estimators into eigencore. Those remain owned
by gprocrustes.

The exact gprocrustes source tarball's tests and vignette code ran successfully
against the candidate installation. `R CMD check --no-manual
--no-build-vignettes` reported four warnings, all outside this conformance
slice: an existing unknown `\\star` Rd macro at installation and Rd checking,
plus the two expected missing-built-vignette warnings caused by
`--no-build-vignettes`. This is not reported as a clean package check.

### DKGE

The public native root object was compared to eigencore's principal root,
Moore-Penrose inverse root, numerical rank, and support projector. Native and
eigencore orthonormalizations were judged by K-Gram postconditions and subspace
projectors, not arbitrary basis signs or rotations. K-Procrustes was compared
to an independently constructed small SVD oracle. Effect-space and root-space
projectors were compared to direct formulas.

The scale bank used `1e-12`, `1`, and `1e12`. Eigencore retained rank two at all
three scales. DKGE agreed at 1 and `1e12`; at `1e-12`, its public
orthonormalizer raised:

```text
`W` must have full column rank in the K metric; its Gram matrix is singular.
```

At this exact DKGE commit, the block-Gram decision uses
`1e-10 * max(1, max(abs(eigenvalues)))`. The absolute floor explains the
observed positive-rescaling failure. The gate requires this divergence to
remain explicit until DKGE changes its native policy; it does not weaken
eigencore's frozen Frobenius-relative policy. It is also evidence that DKGE's
native implementation must remain a differential oracle rather than being
retired automatically.

The exact DKGE source tarball's tests and all 19 vignette code files ran
successfully against the candidate installation. `R CMD check --no-manual
--no-build-vignettes` reported three warnings: a pre-existing compiler warning
for unknown group `-Wfixed-enum-extension` and the two expected missing-built-
vignette warnings. This is not reported as a clean package check.

DKGE continues to own design construction, requested-estimand admission, rank
guards, cross-validation saturation, spatial regularization, contrasts,
cross-fitting, inference, transport, and scientific interpretation.

### rfugw defer decision

rfugw commit `65b9a1b5094aa6fd30cf99a3f8e5eb9a4c1b96ad`, version 0.1.0,
does not depend on eigencore. Its graph diffusion helper operates on a
normalized adjacency spectrum, not a certified PSD metric factor. Its
structure compressors use general SVD, and
`dense_gromov_wasserstein_plan_svd()` explicitly performs a post-hoc SVD only
after the dense plan and dense structures already exist. Replacing these paths
would not alter their dominant memory order or certify the OT objective,
Sinkhorn state, mass policy, or convergence semantics. Adoption is therefore
deferred without delaying eigencore 1.3.

## Ownership and dependency direction

The installed DESCRIPTION records prove:

- eigencore does not Depend on, Import, or Suggest gprocrustes, DKGE, or rfugw;
- gprocrustes declares its existing eigencore import;
- DKGE remains independent of eigencore for this differential gate;
- rfugw remains outside the release dependency graph.

The conformance script is tooling, not ordinary eigencore package code. It
requires exact provenance variables and verifies that all three tested
packages were loaded from the named isolated library. It contains no
triple-colon calls.

## Reproduction

Build exact source tarballs from committed trees, install all three packages
into one empty library, then run the script from a directory outside every
checkout:

```sh
LC_ALL=C LANG=C \
R_LIBS="${candidate_lib}:${R_LIBS_USER}" \
EIGENCORE_CONFORMANCE_LIB="${candidate_lib}" \
EIGENCORE_SOURCE_SHA="${eigencore_source_sha}" \
EIGENCORE_TARBALL_SHA256="${eigencore_tarball_sha256}" \
GPROCRUSTES_SOURCE_SHA="${gprocrustes_source_sha}" \
GPROCRUSTES_TARBALL_SHA256="${gprocrustes_tarball_sha256}" \
DKGE_SOURCE_SHA="${dkge_source_sha}" \
DKGE_TARBALL_SHA256="${dkge_tarball_sha256}" \
Rscript /absolute/path/to/tools/downstream-psd-conformance.R
```

Success prints `PASS`, the check count, seed, exact installed versions, library
path, the pinned DKGE differential, source commits, and tarball SHA-256 values.
The exact-release gate must preserve that complete receipt in the release
validation report.
