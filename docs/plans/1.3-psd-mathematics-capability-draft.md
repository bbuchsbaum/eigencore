# DRAFT: real-double PSD mathematics and capability model

Status: nonbinding design input for `bd-01M0V97EFJ91TKKSH3KH09WMJE`.

This document deliberately does **not** freeze exported names, classes,
condition names, result fields, serialization schemas, or implementation
routes. Candidate labels appear in italics or code font only so that the next
contract task can discuss them precisely. Nothing here is an implementation,
performance, installation, or release claim.

The first admitted scope is finite real-double symmetric positive-semidefinite
(PSD) forms. Complex Hermitian inputs, generic exact matrix-free spectral
claims, and application-specific admissibility rules are deferred.

## 1. Ownership and boundary

Eigencore should own representation-aware numerical geometry:

- validation of symmetry and positive semidefiniteness;
- numerical rank relative to declared tolerances and evidence;
- image and null-space representations;
- factor, projector, pseudoinverse, reduction, and lift actions;
- repair/truncation provenance, source identity, retained memory, and work;
- numerical certificates for every advertised capability.

Callers still own whether singularity is scientifically admissible, the
minimum useful rank, the meaning of null directions, the estimand, and any
domain-specific exactness policy. In particular, eigencore must not absorb
Procrustes, kernel-CV, optimal-transport, or inferential semantics.

The existing generalized-eigen boundary remains unchanged:
`eigen_problem(metric = )` and Hermitian `eig_partial(A, B = )` require an
SPD/Hermitian metric. A singular PSD form enters a downstream computation
through an explicit image reduction; it is not accepted as a generalized
metric merely because it has a square-root-like factor.

## 2. Mathematical model and glossary

Let `K` be an `n` by `n` real symmetric PSD matrix with eigendecomposition

```text
K = Q Lambda Q^T,
Lambda = diag(lambda_1, ..., lambda_n),
lambda_i >= 0.
```

After applying the declared classification policy, let `I_r` index retained
positive eigenvalues, `r = |I_r|`, `Q_r = Q[, I_r]`, and
`Lambda_r = diag(lambda_i : i in I_r)`.

The following terms are used consistently:

- **form**: `q_K(x, y) = x^T K y`;
- **seminorm**: `||x||_K = sqrt(x^T K x)` on the original space;
- **image**: `image(K) = span(Q_r)` at the declared numerical tolerance;
- **null space**: `null(K) = image(K)^perp` at that tolerance;
- **image projector**: `P = Q_r Q_r^T`;
- **null projector**: `N = I - P`;
- **principal square root**: `K^(1/2) = Q_r Lambda_r^(1/2) Q_r^T`;
- **Moore-Penrose inverse square root**:
  `K^(+1/2) = Q_r Lambda_r^(-1/2) Q_r^T`;
- **Moore-Penrose pseudoinverse**:
  `K^+ = Q_r Lambda_r^(-1) Q_r^T`;
- **canonical reduction**: `R = Lambda_r^(1/2) Q_r^T`, an `r` by `n`
  action satisfying `R^T R = K_r`, where `K_r` is the classified/repaired
  PSD action;
- **canonical lift**: `R^+ = Q_r Lambda_r^(-1/2)`, an `n` by `r` action;
- **repair defect**: a recorded norm of the difference between the admitted
  symmetric source and the classified/repaired action;
- **numerical rank**: the number of eigenvalues retained relative to the
  declared rank threshold, not an exact-arithmetic assertion.

`K` defines a seminorm on `R^n`. It defines a metric only after restriction to
`image(K)` or passage to the quotient `R^n / null(K)`. No public wording should
call a singular `K` a metric on the unreduced original space.

### 2.1 Required identities

For compatible vectors or blocks, a certified spectral factor should support
the following identities up to its recorded numerical bounds:

```text
P^T = P                    P^2 = P
N^T = N                    N^2 = N
P N = 0                    P + N = I
K P = P K = K_r            K_r N = 0
R^T R = K_r                R R^+ = I_r
R^+ R = P                  K_r K^+ = K^+ K_r = P
K^(1/2) K^(+1/2) = P       K^(1/2) K^(1/2) = K_r
||R x||_2^2 = x^T K_r x
```

When clipping or explicit truncation changes the action, these equations refer
to `K_r`, not silently to the original source. The certificate must make that
distinction visible.

Eigenvectors inside a repeated eigenspace are not individually identifiable.
Comparisons therefore use projectors, principal angles, or action agreement;
raw eigenvector signs, orientations, and bases are not contract values.

## 3. Candidate tolerance mathematics

There are three independent decisions: symmetry admission, PSD admission, and
effective rank. A single `tol` is insufficient because changing a rank policy
must not make an asymmetric or materially indefinite matrix valid.

The candidate model has non-negative finite absolute and relative inputs for
each decision:

```text
tau_sym  = abs_sym  + rel_sym  * s
tau_psd  = abs_psd  + rel_psd  * s
tau_rank = abs_rank + rel_rank * s
```

The common matrix scale candidate is the spectral norm of the symmetric
surrogate, `s = ||S||_2 = max_i |lambda_i(S)|`. Identity and diagonal
representations compute it structurally. Dense representations compute it
from the complete symmetric eigendecomposition. A sparse or supplied path may
claim this scale only when its evidence actually establishes it; otherwise it
must use and name another certified scale or withhold capabilities that depend
on `s`.

The symmetry defect is measured before spectral classification:

```text
d_sym = ||A - A^T||_2                 (candidate normative defect)
S     = (A + A^T) / 2                 (only after d_sym <= tau_sym)
```

An implementation may use a certified upper bound instead of explicitly
forming `A - A^T`, but must record the bound and its provenance. Frobenius norm
is a possible implementation aid, not an interchangeable public threshold.

### 3.1 Zero-scale behavior

If `s = 0`, all relative contributions are exactly zero. With zero absolute
tolerances, only exact symmetry and an exact zero spectrum are admitted. A
nonzero absolute tolerance deliberately creates a unit-dependent neighborhood
around zero and must be recorded. The implementation must not replace `s`
with `max(1, s)` because that makes classification depend on arbitrary units
and breaks positive-rescaling behavior.

### 3.2 Classification order and boundaries

For a symmetry-admitted `S`, classify every original eigenvalue before any
repair:

1. `lambda < -tau_psd`: materially negative; reject PSD certification.
2. `-tau_psd <= lambda < 0`: accepted within-tolerance negative; retain the
   original value in provenance and clip it to zero in `K_r`.
3. `lambda == 0`: exact zero.
4. `0 < lambda <= tau_rank`: positive numerical-null value; set it to zero in
   `K_r` under the effective-rank policy.
5. `lambda > tau_rank`: retained positive value.

The inclusive boundaries above are candidates but must be frozen explicitly.
Tests must include the exact boundary and its adjacent representable doubles.
If user truncation removes a value above `tau_rank`, label it separately as
user-truncated. User truncation changes spectrum coverage and cannot be
reported as complete numerical nullity of the source.

The contract task must decide whether `tau_rank >= tau_psd` is required. They
serve different purposes, so silently replacing either one by their maximum is
not acceptable.

### 3.3 Positive rescaling

When all absolute tolerances are zero and the relative policies use a
positively homogeneous certified scale, classification is invariant under
`K -> c K` for every finite `c > 0`. Nonzero absolute tolerances intentionally
break that invariance near zero. Overflow or underflow that makes the scaled
input non-finite is an input failure, not a classification result.

For illustration only, take `rel_psd = 1e-10`, `rel_rank = 1e-8`, all absolute
tolerances zero, and

```text
K_c = c * diag(4, 1, 1e-9, -1e-11).
```

| `c` | `s` | `tau_psd` | `tau_rank` | classification |
|---:|---:|---:|---:|:---|
| `1e-12` | `4e-12` | `4e-22` | `4e-20` | retain, retain, positive-null, accepted-negative |
| `1e-6`  | `4e-6`  | `4e-16` | `4e-14` | same |
| `1`     | `4`     | `4e-10` | `4e-8`  | same |
| `1e6`   | `4e6`   | `4e-4`  | `4e-2`  | same |
| `1e12`  | `4e12`  | `4e2`   | `4e4`   | same |

This table is an adversarial test template, not a recommendation of defaults.

### 3.4 Repair record

Within-tolerance repair does not rewrite history. A complete record needs at
least:

- the admitted symmetric spectrum before clipping/truncation;
- the classified spectrum used by actions;
- indices or counts for every classification category;
- resolved scale and all three resolved thresholds;
- symmetry and spectral repair defects, with named norms;
- whether the action represents the source exactly, a repaired source, or an
  approximation with a bound.

For complete orthogonal spectral factors, candidate defects include

```text
d_sym    = ||A - A^T||_2
d_repair = ||S - K_r||_2 = max_i |lambda_i(S) - lambda_i(K_r)|.
d_total  = ||A - K_r||_2
```

`d_total` is the direct source-to-action defect when it is computed. If a
representation provides only certified upper bounds, the record must say so
and retain separate symmetry and spectral-repair terms; neither component may
disappear inside one optimistic scalar.

An input with a materially negative eigenvalue is indefinite. Clipping it must
not produce a certified-PSD object. If a future transformation API permits
deliberate projection onto the PSD cone, it must be a separately named action
whose certificate says the original input failed PSD validation.

## 4. Pseudoinverse application versus strict solve

Moore-Penrose application is total:

```text
x_mp = K^+ b
```

is defined for every finite compatible `b`; it solves the projected problem
`K x = P b` and returns the minimum-Euclidean-norm representative.

A strict solve of `K x = b` is partial. It first checks

```text
d_rhs = ||(I - P) b||_2
tau_rhs(b) = abs_rhs + rel_rhs * ||b||_2.
```

It succeeds only when `d_rhs <= tau_rhs(b)` and then returns `K^+ b` together
with compatibility evidence. For block right-hand sides, compatibility is
checked and reported per column; one incompatible column cannot be hidden by a
large aggregate norm. Failure must be a typed incompatible-right-hand-side
condition containing the offending columns, defects, thresholds, factor
identity/revision, and no partial result unless the future contract explicitly
defines one.

## 5. Multidimensional evidence model

No single `exact` flag can express what users need to know. A factor/action
record needs four independent axes plus quantitative details.

### 5.1 Spectrum coverage

- **complete**: every eigenvalue relevant to classification was computed;
- **structural**: an exact zero subspace and any required spectral bounds
  follow from a named representation theorem without enumerating the spectrum;
- **partial**: only a stated spectral subset is known;
- **estimated**: stochastic or iterative estimates with recorded uncertainty.

Complete evidence may support complete tolerance-relative rank/nullity claims.
Structural evidence may do so only when it establishes both the zero subspace
and a certified lower bound placing every remaining spectral value above the
declared rank threshold. Otherwise it supports algebraic nullity and numerical
rank bounds, which must remain distinct. Partial or estimated evidence may
support bounds only; absence of a discovered negative eigenvalue is not PSD
validation.

### 5.2 Validation evidence

- **computed**: eigencore performed the required checks;
- **supplied-certified**: a supplied factor/certificate satisfies a frozen
  certificate contract and identity check;
- **user-declared**: trusted assertion without independent validation;
- **unavailable**: no admissible validation evidence.

User declaration is provenance, never computed certification.

### 5.3 Action fidelity

- **exact-for-certified-factor**: the action is the algebraic action of the
  stored/certified finite-double factor;
- **repaired-with-defect**: the action is exact for `K_r`, with a recorded
  source-to-action defect;
- **approximate-with-bound**: an approximation with a named, applicable bound.

“Exact” here never means exact real arithmetic and never upgrades incomplete
spectrum coverage.

### 5.4 Source semantics

- **immutable-snapshot**: the factor owns or hashes an immutable snapshot;
- **live-versioned-source**: reuse is valid only while source identity and
  revision match;
- **uncacheable-opaque-source**: no stable revision, so cached spectral state
  cannot be reused across calls or sessions.

Every public capability decision should be explainable as a function of these
axes, the quantitative certificate, and the requested action.

## 6. Draft representation/action capability matrix

`yes` means a candidate first-release capability when its preconditions are
certified. `conditional` means only an explicitly admitted representation can
provide it. `no` means fail before expensive work. This table is a design
draft, not an API promise.

| Representation | `K x` | principal root | inverse root | `K^+ x` | projector | rank/nullity | canonical reduction/lift | portable reuse |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| identity | yes, structural | yes | yes | yes | yes | yes | yes | yes |
| real finite diagonal | yes, structural | yes | yes | yes | yes | yes | yes | yes |
| real finite dense symmetric | yes, complete | yes | yes | yes | yes | yes | yes | yes if snapshot identity is portable |
| admitted structural sparse | yes | conditional | conditional | conditional | conditional | algebraic nullity; numerical rank only with a threshold-separating bound | conditional | representation-specific |
| supplied certified spectral factor | yes | yes | yes | yes | yes | complete if certificate says so | yes | only if certificate and source identities are portable |
| supplied certified Gram factor `K = L L^T` | yes | no by implication alone | no by implication alone | conditional after admitted rank factorization | conditional | conditional | noncanonical `L^T` action only unless canonicalized | representation-specific |
| opaque matrix-free apply only | apply only | no | no | no | no | no | no | no cached spectral reuse |

Important exclusions:

- A generic sparse matrix is not certified PSD merely because it is symmetric.
- A partial eigensolver cannot establish exact nullity or PSD of the unseen
  spectrum.
- A Gram factor `L` is not generally the principal square root of `L L^T`.
- A matrix-free `K x` callback does not imply square-root, inverse, projector,
  rank, or nullity capabilities.
- Tests may densify small fixtures as independent oracles; advertised sparse
  implementation paths may not densify.

Candidate admitted structural sparse examples include diagonal storage and a
factor-defined Gram/Laplacian form whose algebraic theorem, dimensions, source
identity, and rank preconditions are explicit. Merely recognizing a sparse
storage class is insufficient.

## 7. Draft state machine

```text
raw source
  -> invalid input                         [shape/dtype/nonfinite]
  -> symmetry rejected                    [d_sym > tau_sym]
  -> symmetry admitted
       -> materially indefinite           [lambda_min < -tau_psd]
       -> PSD classified
            -> exact-for-source action     [no repair/truncation]
            -> repaired action             [small negatives or rank truncation]
            -> capability unavailable      [insufficient evidence]

any reusable state
  -> reusable                              [same identity and revision]
  -> invalidated/recomputed                [changed revision]
  -> nonportable failure                   [session change or unsupported source]

any action request
  -> supported action + fresh action evidence
  -> stable unsupported-action failure
  -> strict-solve compatibility failure
```

Material indefiniteness is terminal for PSD certification. A stale source is
not repaired by recomputing an integrity token over mutated fields; it requires
fresh validation from the current source identity/revision.

## 9. Worked design examples

These examples specify expected mathematics, not public syntax.

### 9.1 Zero form

For `K = 0_(n x n)` with zero absolute tolerances: rank `0`, nullity `n`,
`P = 0`, `N = I`, reduction has shape `0 x n`, lift has shape `n x 0`, and
all root/pseudoinverse actions return conformable zeros. Strict solve accepts
only right-hand sides compatible with zero under the RHS tolerance.

### 9.2 Diagonal SPD form

For `K = diag(9, 4, 1)`: rank `3`, `P = I`, `R = diag(3, 2, 1)`, lift
`diag(1/3, 1/2, 1)`, and strict solve agrees with ordinary diagonal solve.
No dense eigendecomposition is needed or allowed by the representation path.

### 9.3 Dense singular PSD form

Choose an orthogonal `Q` and `K = Q diag(9, 1, 0, 0) Q^T`. Rank is `2`;
raw eigenvectors may rotate within repeated subspaces, but `P`, `K^+`, the
reduction energy, and strict compatibility are invariant.

### 9.4 Sparse graph Laplacian

A graph Laplacian has structural PSD evidence but its nullity depends on the
number of connected components. Connectivity establishes algebraic nullity.
It establishes tolerance-relative numerical rank only if a certified positive
spectral lower bound also exceeds `tau_rank`; otherwise the result must expose
bounds or keep numerical rank unavailable. Sparse storage plus approximate
smallest eigenpairs is insufficient. Any principal-root or pseudoinverse
action remains unsupported until separately admitted without hidden dense
conversion.

### 9.5 Supplied factor

For `K = L L^T`, `L^T` is a valid Gram reduction because
`(L^T)^T L^T = K`. It is not generally the canonical spectral reduction and
`L` is not generally the principal square root. Capabilities depend on the
supplied certificate, dimensions, rank evidence, and source identity.

### 9.6 Opaque apply callback

A callback that computes `K x` and declares `structure = hermitian()` can
support only application unless additional admitted evidence is supplied.
The system must fail stably for exact rank, nullity, root, inverse root,
projector, and canonical reduction requests before running an iterative probe.

## 10. Open-decision register for contract freeze

All items below are intentionally unresolved here.

1. Public constructor, coercion, accessor, and action names.
2. Whether source wrappers and certified factors are separate public classes
   or disjoint states of one public abstraction.
3. Exact schema and print behavior for PSD validation/action certificates.
4. Stable condition class hierarchy and codes for invalid input, asymmetry,
   indefiniteness, unsupported action, incomplete evidence, stale source,
   nonportable state, and incompatible RHS.
5. Default absolute/relative tolerances and whether `tau_rank >= tau_psd`.
6. Norm used as the normative symmetry defect and how sparse certified upper
   bounds are represented.
7. Whether symmetry-admitted inputs are symmetrized automatically or require
   an explicit repair policy.
8. Whether positive values at exactly `tau_rank` are discarded (the candidate
   above says yes).
9. Whether deliberate user truncation belongs in the constructor or a
   separate transformation.
10. Factor identity derivation, revision semantics, and cache keys.
11. Snapshot versus live-source defaults and mutation/invalidation behavior.
12. Portable serialization of spectral factors, structural sparse records,
    supplied certificates, and native handles.
13. How factor-construction and action work extend or complement
    `eigencore_work` schema version 1.
14. Which retained arrays and native allocations are mandatory components of
    `eigencore_memory`.
15. Which structural sparse forms are admitted in 1.3 and which actions each
    one exposes.
16. Whether a supplied Gram reduction is public in 1.3 even when canonical
    spectral actions are unavailable.
17. Exact RHS compatibility norm, default tolerances, and block-failure shape.
18. Capability-query shape and whether unsupported capability is inspectable
    without attempting the action.
19. Interaction between repaired actions and downstream callers that require
    source-exact application.
20. Complex-Hermitian future migration without weakening the real-double
    first-release contract.

Items 2-4, 10-14, and 18-19 are specifically owned by the common-contract
dependency `bd-01KZZYZ28F0TMGVFKNSQCDKY7V`; the remaining items must still be
checked for interaction with that dependency before freeze.

The next task may freeze these only after reconciling them with the published
1.2 contract and the diagnostic test strategy. Any change to a 1.2-owned
identity, serialization, certificate, work, memory, or API-snapshot rule needs
