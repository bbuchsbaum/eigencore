# Eigencore 1.3 PSD release validation

Date: 2026-08-25

Candidate: frozen `eigencore` 1.3.0 release payload

Scope: integrated local certification of the admitted real-double PSD
capability. Hosted cross-platform checks and publication receipts remain
separate release gates.

## Outcome

The integrated 1.3 candidate passes its source, numerical, resource,
documentation, installed-downstream, sanitizer, and preliminary exact-artifact
gates. The source tarball is rebuilt after this report content is finalized so
that the checked bytes are derived from the exact commit that contains the
complete evidence record. Repository planning reports are deliberately absent
from the package tarball under `.Rbuildignore`; they remain attached to the
same immutable source commit.

The release admits complete identity, diagonal, dense spectral, and dense Gram
factors, plus structural sparse Gram and graph-Laplacian factors. It does not
admit generic sparse symmetric factorization or an opaque matrix-free
approximation route. Unsupported capabilities fail closed and are covered by
stable negative tests.

The exact release commit, tarball SHA-256, hosted checks, tag, live `main`, and
downloaded-asset receipts cannot be embedded in the tarball whose digest they
identify. They are recorded by the release Mote and GitHub Release after the
same bytes pass every exact-artifact gate.

## Diagnostic test evidence

- The dedicated adversarial campaign passed 230 assertions with zero failures,
  warnings, or skips.
- The PSD bank passed 781 assertions: 82 API/contract, 259 factor, 54
  image-space, 156 sparse/structural, and 230 adversarial assertions.
- The complete source suite passed 6,241 assertions with `NOT_CRAN=true` and
  zero failures, warnings, or skips. This setting is material because the
  default local mode intentionally omits optional property and benchmark-
  contract cases.
- Mutation checks killed wrong square-root powers, missing reduction weights,
  reversed threshold equality, an absolute scale floor, erased negative-source
  evidence, a mislabeled Gram factor, ordinary inverse/null-mode inversion,
  permissive incompatible solves, arbitrary repeated-eigenvector comparison,
  sparse densification, unsupported evidence promotion, and incomplete
  retained-memory accounting.

The decisive oracles are not restatements of the production branch. They use
analytic diagonal actions, independently assembled spectral actions, direct
Moore-Penrose and projector laws, explicit quotient energies, small dense graph
actions, independent graph components, and projector comparisons for repeated
eigenspaces. Boundary fixtures use adjacent floating-point values around the
threshold, and scale fixtures use `1e-12`, `1`, and `1e12`.

Full fixtures, seeds, numerical bounds, failure fields, and mutation-to-test
mapping are recorded in
[`1.3-psd-certification-report.md`](1.3-psd-certification-report.md) and
[`1.3-psd-test-strategy.md`](1.3-psd-test-strategy.md).

## Admitted capability manifest

| Representation | Evidence | Admitted capability | Dense `n` by `n` state |
|:---|:---|:---|:---:|
| identity | complete | every canonical action, image/block primitives, rank and both nullities | no |
| diagonal | complete | every canonical action, image/block primitives, rank and both nullities | no |
| dense spectral | complete | every canonical action, image/block primitives, numerical rank/nullity | yes |
| dense Gram | complete | compact-SVD actions, image/block primitives, numerical rank/nullity | yes |
| sparse Gram | structural | form, Gram, serialization, cache reuse | no |
| sparse Laplacian | structural | form, Gram, component-count algebraic nullity, serialization, cache reuse | no |

Generic sparse symmetric matrices fail before dense conversion. Opaque
operators without a future admitted callback certificate fail without even one
callback invocation. Structural factors reject complete-spectrum, root,
pseudoinverse, projector, quotient, strict-solve, block, and reduced-operator
requests before fallback or densification.

## Sparse resource evidence

Fresh processes exercised 50,000-row sparse Gram and path-Laplacian factors.
The corresponding dense matrix alone would require 20,000,000,000 bytes. The
loaded-package baseline maximum RSS was 166,871,040 bytes.

| Route | Source bytes | Retained bytes | R cumulative allocation | Maximum RSS | Action time |
|:---|---:|---:|---:|---:|---:|
| sparse Gram, width 32 | 601,632 | 656,344 | 5,310,512 | 189,743,104 | 0.005 s |
| path Laplacian | 2,001,480 | 1,656,616 | 150,359,816 | 282,443,776 | 0.011 s |

Both factors reported `dense_n_by_n = FALSE`, retained sparse state, passed
construction certificates, and completed four-column form application. An
`as.matrix()` trace and retained-state inspection independently guard against
advertised sparse routes silently becoming dense. Timing is diagnostic, while
the representation, memory-order, and correctness conditions are gates.

## Documentation and package site

- The new executable `psd-geometry` guide covers factor construction,
  diagnostics, canonical actions, quotient reduction/lift, block
  orthonormalization, strict solve versus pseudoinverse, a reduced generalized
  eigenproblem, admitted sparse constructors, persistence, and typed
  unsupported paths.
- The guide states the ownership boundary: eigencore owns numerical PSD
  geometry; downstream packages retain application estimands, gauges,
  objectives, validation, and interpretation.
- The guide, updated overview vignette, and generated README rendered
  successfully.
- A complete pkgdown build passed URL, metadata, reference, article, news,
  sitemap, redirects, and search-index generation.
- The new PSD guide has no `lintr` findings. The full repository retains seven
  pre-existing style findings; the hosted lint workflow is therefore
  diagnostic and configured not to fail solely on those findings.

The guide also documents one honest API boundary: a generic reduced operator
does not have exact operator-norm metadata, so a large partial solve may
withhold certification despite a small residual. The admitted small complete
example uses exact rank-sized dense image geometry. No broader matrix-free
claim follows.

## Hosted and publication boundary

Local evidence does not establish Linux, Windows, R-devel, oldrel, GitHub
Pages, or public-download behavior. Publication therefore remains blocked
until the pull request passes the five-platform R CMD check matrix plus hosted
documentation, coverage, lint, and benchmark-workflow validation. The release
then requires all of the following to identify the same committed payload:

1. local branch, tracking branch, live `main`, annotated `v1.3.0` tag, and
   GitHub Release target;
2. one final `eigencore_1.3.0.tar.gz` checked, installed, certified, and
   downstream-tested by path;
3. the uploaded asset downloaded again and matched to the recorded SHA-256.

Any mismatch, hosted failure, exact-artifact error/warning/note, sanitizer
diagnostic, downstream conformance failure, or publication-receipt failure
blocks the release.
