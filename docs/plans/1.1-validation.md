# Eigencore 1.1 local validation

Date: 2026-08-24

Candidate: frozen `eigencore` 1.1.0 release payload

Scope: integrated local release gate; hosted cross-platform checks remain a
separate release step.

## Outcome

The integrated 1.1 candidate passes the local correctness, benchmark-contract,
documentation, package-site, and exact source-tarball gates described below.
The source tarball was rebuilt after this report content was finalized, so the
verified artifact includes the complete evidence record.

The benchmark gates are correctness and provenance gates. Timing and allocation
ratios are recorded, but a passing gate is not presented as a general
performance ranking.

## Headline benchmark gates

### Hermitian continuation and warm starts

Command:

```sh
Rscript inst/benchmarks/bench-warm-start-continuation.R --strict
```

The non-quick gate covered five regimes: two `dgCMatrix`, two dense, and one
callback-only matrix-free operator. Each regime ran an eight-step parameter
sweep, including a deliberate overlap-loss step. Cold and warm solutions
certified, agreed with each other, and agreed with an independent dense oracle
where the oracle was enabled. The gate also checked:

- native block-Lanczos provenance on every row and the matrix-free callback
  label on the callback rows;
- exact operator block-call, operator-column, and certification-column
  accounting;
- fresh certificates after each warm solve; and
- the exported-API continuation integration (`8249` operator columns, `1589`
  certification columns, all rows certified).

Final strict flags:

```text
correctness_ok=TRUE overlap_loss_exercised=TRUE accounting_ok=TRUE
coverage_ok=TRUE provenance_ok=TRUE
```

### Implicit-Gram partial SVD

Command:

```sh
Rscript inst/benchmarks/bench-implicit-gram-svd.R --strict --iterations=1
```

The new strict gate exercises the production `auto()` route at the same large
regimes used to motivate 1.1, plus a wide sparse regime and an actual fallback
transition:

| Case | Size / rank | Contract result | Fastest certified reference | Reference / eigencore time |
|---|---:|---|---|---:|
| dense tall | 4000 x 1000, k=10 | implicit, exact two-sided certificate | RSpectra | 0.35x |
| dense square | 2000 x 2000, k=10 | implicit, exact two-sided certificate | RSpectra | 0.45x |
| sparse tall | 20000 x 5000, k=10 | implicit, exact two-sided certificate | RSpectra | 0.49x |
| sparse tall | 20000 x 5000, k=50 | implicit, exact two-sided certificate | RSpectra | 0.86x |
| sparse wide | 1500 x 10000, k=10 | implicit, exact two-sided certificate | irlba | 0.56x |
| rank-deficient dense | 180 x 100, k=6 | implicit certificate rejected; certified native Golub-Kahan fallback used | not applicable | not applicable |

All six contracts passed. Production rows reported
`normal_operator_implicit = TRUE`, `materialized_gram = FALSE`, and
`certified_in_original_coordinates = TRUE`; left and right residuals and
backward errors were finite, and the exact certificate scale was not estimated.
The rank-deficient probe reported the failed implicit certificate, attempted
and selected the named native Golub-Kahan fallback, and returned a passing
two-sided certificate.

The time ratios above are deliberately reported as observed: values below one
mean eigencore was slower than the named current external solver on this host.
They do not contradict historical same-package speedups versus the routes that
eigencore itself used before the implicit implementation, but they do preclude
a broader competitive-speed claim from this run.

### Path-Laplacian allocation blocker

The final installed G1 refresh reproduces and resolves the R-allocation
regression that blocked publication. Sparse tridiagonal bands are parsed once
per solve and reused for routing, shift perturbation, native factorization, and
certification. The native standard tridiagonal kernel returns only the selected
Ritz values and `n x k` Ritz vectors, not its internal Krylov basis.

At `path_laplacian:1000`, `k = 20`, cumulative R allocation fell from
3,820,632 to 1,510,696 bytes; the exact strict row certified 20/20, ran at
0.006210065 seconds, and was 7.53753 times faster than RSpectra. The full
`n = 10000` row also certified 20/20 and ran at 0.02310243 seconds. Because
R's allocation profiler cannot see any compared engine's native working heap,
the cross-engine `mem_alloc` ratio remains diagnostic. The strict memory gate
instead bounds the retained solver result to at most 1.25 times the smallest
certified reference result; the observed ratios were 0.8732987 and 0.9856059.
No peak-RSS claim is made.

## Fresh native sanitizer gate

The 1.1 candidate was rebuilt with undefined-behavior instrumentation and the
installed native smoke was run with abort-on-first-error semantics:

```sh
EIGENCORE_SANITIZER_CXXFLAGS='-fsanitize=undefined -fno-sanitize-recover=undefined' \
EIGENCORE_SANITIZER_LIBS='-fsanitize=undefined' \
  R CMD INSTALL --preclean --clean --library=/tmp/eigencore-ubsan-lib .

UBSAN_OPTIONS='halt_on_error=1:print_stacktrace=1' \
  Rscript -e 'library(eigencore, lib.loc = "/tmp/eigencore-ubsan-lib"); source(system.file("validation/native-smoke.R", package = "eigencore"))'
```

The sanitizer flags were present on every native compilation and on the final
shared-library link. The installed-package path was checked before the smoke;
it completed with `eigencore native smoke passed` and no UBSan diagnostic.
`src/Makevars` exposes the two package-specific opt-in variables above so the
linker instrumentation cannot be lost behind the package's LAPACK/BLAS link
definition.

The post-V1 benchmark workflow now runs its smoke tier for pull requests and
on the weekly schedule. That tier includes matrix-free operator sidecars plus
the quick strict warm-start continuation and implicit-Gram SVD gates. Strict
and long profiles remain explicitly dispatchable release/diagnostic runs.

## Documentation and package site

- `certificates.Rmd`, `eigencore.Rmd`, and `sparse-pca.Rmd` rendered
  successfully after the certificate-language revision.
- `README.Rmd` rendered successfully to a temporary output. `diff -b` against
  the tracked `README.md` was empty; the byte-level difference consisted only
  of trailing spaces emitted by the current knitr/pandoc combination.
- The full pkgdown GitHub-Pages build completed with valid URL, article, and
  reference metadata. It built six source articles, the reference index, news,
  sitemap, search index, and redirects.
- `_pkgdown.yml` now uses the current nested article slug
  `articles/benchmarks`; the previous `benchmarks` entry was a real
  configuration error after that article moved under `vignettes/articles/`.

## Failure classification

Two first-pass pkgdown failures were distinguished rather than suppressed:

1. `Articles metadata not ok ... (benchmarks) must be a known topic or alias`
   was a package configuration defect. The corrected slug passes pkgdown's
   metadata check and builds the intended article.
2. Sandboxed builds could not initialize `processx` or write the default R
   user cache (`Operation not permitted`). A direct benchmark-article render
   passed, and the same full pkgdown command passed with authorized process
   access and its cache redirected to a temporary validation directory. This
   is a host execution restriction, not a package or article failure.

The routine `rvm ... operation not permitted: ps` line is likewise emitted by
the host shell startup and did not change command exit status.

## Final package gate

The final gate builds a fresh source tarball from the committed candidate and
checks that exact tarball:

```sh
R CMD build .
_R_CHECK_CRAN_INCOMING_REMOTE_=false \
  R CMD check --as-cran --no-manual eigencore_1.1.0.tar.gz
```

The exact 1.1.0 tarball completed with `0 errors | 0 warnings | 0 notes` on
R 4.5.1 under macOS Sonoma 14.3. Installation, compiled-code checks, examples,
the full installed test suite, and vignette rebuilding all passed.

A separate attempt with remote incoming lookups enabled was blocked before
package installation by timeouts fetching the Bioconductor package index and
CRAN `archive.rds`. An earlier remote-enabled development-version run completed
with `0 errors | 0 warnings | 1 note`, where the note was the `.9000` version;
it is historical evidence, not validation of this exact release payload. The
final exact-artifact run disabled only those remote metadata lookups; all
`--as-cran` package checks, including installation and the full test and
vignette bodies, remained enabled. Hosted CI is still required for an
independent connected-environment result.

Any error, warning, test failure, compiled-code issue, vignette failure, or
additional note blocks the local gate.

## Remaining release boundary

This document records local macOS evidence only. It does not substitute for
the separate hosted R-release/R-devel/oldrel checks on macOS, Windows, and
Linux, nor for publication checks. No cross-platform or CRAN acceptance claim
follows from the local result. Exact commit, tarball digest, hosted checks, tag,
and live branch receipts are recorded outside this artifact by the release
Mote and GitHub release.
