### Decisions (2026-10-08)

Correctness takes precedence over backward compatibility:

- **C12:** `backward_error` will use the normwise definition
  `||r|| / ((||A||_2 + |lambda| ||B||_2) ||x||)` (SVD: `/ ||A||_2`). The
  denominator uses an `||A||_2` value that never exceeds the true norm: exact
  where cheap (diagonal `max|d|`, dense via the solve's own extreme Ritz value
  when the target includes it), otherwise `max(computed |theta| or sigma,
  short Lanczos/power estimate)`. A lower bound in the denominator makes the
  reported backward error an over-estimate, so `passed` stays sound and is no
  longer up to `sqrt(rank)` more lenient than the standard definition.
  `norm_bound_type` records the source. NEWS will call this out as a
  behaviour change.
- **C15:** `maxit` becomes what its documentation says, an iteration
  (restart) limit. The Krylov subspace size moves to the method descriptors'
  `max_subspace` (already present on `lanczos()`/`golub_kahan()`), and
  RSpectra `opts$ncv` maps there; `opts$maxitr` maps to `maxit`.

New findings from the suite's independent accuracy and target-set checks
(standard profile, 1 thread; details in `results.csv`):

- **P18 (done):** eigencore's 4-thread OpenMP kernels degraded sharply when
  the machine was oversubscribed (load 3-8 on 4 cores from concurrent jobs):
  sparse symmetric 20k LA 0.28 s -> 6.5 s, `svd_partial` 50k x 2k 0.20 s ->
  9.0 s, 50k x 20k 1.1 s -> 13.9 s, 2-D Laplacian SA 1.2 s -> 34 s, with
  identical operator-application counts; single-threaded RSpectra was
  unaffected.
  *Root cause:* libgomp's default (active) wait policy. R links libgomp, so
  it is initialised at R start-up with `OMP_WAIT_POLICY` unset: idle team
  threads spin (GOMP_SPINCOUNT 300000) and every fork/join waits for the
  slowest team member. On busy cores a descheduled member costs a scheduler
  time slice per region, and the spinning members take the CPU it needs;
  a solve has ~1000 short regions (a sparse product of 1e5 nonzeros takes
  ~0.2 ms), hence seconds. Evidence (8 CPU burners, eigencore 1.3.0, 4
  threads, same operator counts): symmetric 20k LA 10.8 s -> 0.62 s and
  `svd_partial` 50k x 2k 7.7 s -> 0.33 s with `OMP_WAIT_POLICY=passive`;
  `GOMP_SPINCOUNT=10000` 1.1 s / 0.68 s; `OMP_DYNAMIC=true` 1.3 s / 1.0 s
  (libgomp's 1-minute load average). The policy cannot be changed from a
  package once libgomp is initialised (no runtime API; `kmp_set_blocktime`
  exists only in LLVM libomp).
  *Fix:* a parallel-efficiency governor (`src/native_operators.cpp`,
  `EigencoreParallelRegion` in `eigencore_common.h`) around every OpenMP
  region (CSC forward gather / slabs / column chunks, adjoint gather,
  randomized projection, LDL' solves, OpenMP reorthogonalisation): each
  region reports its wall time and the master thread's busy time; a region
  slower than threads x master time + 0.1 ms (i.e. slower than serial) is a
  strike, two strikes halve the team, and a doubled team is probed again
  after 0.25 s (doubling to 4 s while probes keep failing). Only
  `num_threads` changes; algorithm choices (CSR copy, slabs, OpenMP vs BLAS
  reorthogonalisation) still follow `eigencore.threads`, so results are
  independent of the load (thread-determinism check passes, also under 8
  burners). The adjoint panel transpose + gather and the projection
  transpose + gather now run in one region each. `eigencore.adaptive_threads
  = FALSE` disables it. Default thread count also limited to physical cores
  and the cgroup CPU quota (kept multithreaded: unloaded 4 threads is 1.2-1.4x
  faster than 1 on these cases and the governor makes it safe). Timings

### 3.1 Complex Hermitian iterative routes (T6, 2026-10-10)

Before: complex Hermitian problems worked only on the dense zheev route.
`lanczos()` on complex input errored in `reorthogonalize_against`
(double-only native kernel), reference `lobpcg()` returned unconverged
values (real inner products: `colSums(X * AX)`, `crossprod()`), complex
matrix-free operators and complex pencils errored, `nearest()` on a small
dense complex matrix errored (implicit real shift-invert), and every complex
iterative result stayed `target_completeness = "not_checked"`, hence
`passed = FALSE` under the strict contract.

**Approach: realification, not a native complex kernel.** `H = A + iB` maps
to the real symmetric `R(H) = [A -B; B A]` of size `2n` (eigenvalues of `H`
each doubled, eigenvectors `(x; y)` and `(-y; x)` for `z = x + iy`). The
complex problem is planned as the real problem `(R(H), R(M))` with `2k`
pairs through the ordinary planner (`R/complex_hermitian.R`; plan label
`native realified complex Hermitian route (real 2n embedding)`), so the
native dense/CSC/matrix-free block Lanczos, CHOLMOD shift-invert, C60
routing, generalized Lanczos, interval slicing and the completeness
machinery (probe, LDL' inertia counts, repair) all run unchanged. The `2k`
real Ritz vectors are mapped back by a complex Rayleigh-Ritz step: `Z = top
+ i bottom` has complex rank `k` (singular values `sqrt(2)` and the solve's
error level; the rank is taken where the gap shows it), an M-orthonormal
basis of `span(Z)` is projected onto `H`, and the `k` target pairs are
certified from scratch on the complex operator. The real verdict transfers
when the real set is the doubled complex set (even count, complex rank
`m/2`); otherwise the mapped set is re-checked. Inner method: block Lanczos
(`block = 2 * block`, at least 2; auto: block 4 for dense `n >= 500`, else
2) for largest / largest_magnitude / smallest (sparse smallest keeps the
real `auto()` for C60), real `auto()` for nearest / both_ends /
smallest_magnitude / pencils, `shift_invert(sigma)` (real `sigma`; a user
`solve` is wrapped) for transforms. `lobpcg()` stays on the reference
complex LOBPCG (complex preconditioners and constraints keep working).

Why not native complex: a complex block Lanczos would need the 3400-line
`src/block_lanczos.cpp` templated on the scalar type plus complex variants
of the probe and inertia kernels. Its gain is bounded by the operator-work
ratio: the embedding finds every complex direction twice, so a native
complex kernel needs at most about half the operator columns (the
reference complex Lanczos used 120 columns where the realified block-2 run
used 310 at n = 300, but with a much larger unrestarted subspace). The
measured realified route is already well ahead of the old dense route and
equal in accuracy, so the native kernel is deferred.
